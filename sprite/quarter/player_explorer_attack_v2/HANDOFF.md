# 플레이어 8방향 단검 2연타

2연타 제작 당시 커밋 `669c394`의 탐험가를 기준으로 삼았다. 얼굴·머리·복장 파츠는 원본 방향별 프레임에서 분리했다. 옆모습 등에서 가려진 일부 사지는 같은 방향의 원본 보행·공격 프레임을 사용했다. 단검은 기존 동쪽 베기에서 분리해 모든 방향에 같은 크기로 사용했다.

## 게임 시트

게임은 이 폴더의 512×2240 RGBA 시트 `explorer.png`와 메타데이터 `explorer.json`을 읽는다. 공격 클립 외의 셀은 기존 아틀라스의 픽셀을 보존한다. 단검 2연타는 화면 방향별로 `attack-n`, `attack-ne`, `attack-e`, `attack-se`, `attack-s`, `attack-sw`, `attack-w`, `attack-nw`를 사용한다.

- 각 클립은 64×64, 공통 발 기준점 (32,54), 13프레임, 750ms, 비반복이다.
- 프레임 시작은 0, 70, 150, 233, 275, 333, 376, 418, 466, 516, 572, 642, 700ms다. 네 번째와 아홉 번째 프레임이 시작되는 233ms와 466ms에 `hit` 이벤트가 있다.
- 첫 베기의 회수 자세에서 단검을 다시 들어 반대 방향으로 되베고 중립 자세로 돌아온다. 두 번째 베기까지 두 발의 위치를 고정하고 572ms부터 중립 자세로 발을 옮긴다.
- 정지 공격의 시작과 회수가 끝난 700ms에는 해당 방향의 대기 첫 프레임을 사용한다. 단검이 보이는 동안 칼끝은 앞쪽을 향한다. 준비와 회수 사이 손목의 각도는 달라지며, 각 방향의 팔꿈치는 같은 쪽으로 굽힌다.

## 이동 공격과 횃불

- 공격 중에는 시작 방향의 상체를 고정한다. 이동하면 `moving-attack.png`에서 공격 클립의 `upper_layer_rects`와 같은 방향 보행·달리기 클립의 `leg_layer_rects`를 합성한다. 화면 상하좌우로 달리며 공격할 때는 같은 방향의 보행 다리를 사용한다.
- 다리 프레임은 실제 이동 거리에 따라 진행한다. 공격 방향의 뒤쪽으로 이동하면 위상을 역방향으로 적용한다. 이동을 멈추면 2연타의 현재 시점에 맞는 정지 공격 프레임을 그린다.
- 획득한 횃불 불꽃은 대기·보행·달리기·공격 클립의 `torch_mounts`를 따라 가방에 표시된다. 공격 중에는 공격 프레임의 장착점을 사용한다. 화면 북·북동·동·북서 방향에서는 몸 앞에, 나머지 방향에서는 몸 뒤에 불꽃을 합성한다.

## 검격 효과

`sprite/quarter/effects/dagger-slash.json`의 `tip_px`는 13개 신체 프레임 각각의 칼끝 위치를 64×64 프레임 좌상단 기준 논리 픽셀로 담는다. 효과 프레임의 `anchor_px`를 그 칼끝에 맞춰 그린다. 12프레임 효과를 200–400ms와 433–633ms에 재생한다. 두 효과의 세 번째 프레임 시작은 타격 시점인 233ms, 466ms와 일치한다.

8방향의 두 타격 프레임에서 단검이 보이고, 표시된 칼끝 픽셀은 리그 좌표의 1px 이내에 있다. 남쪽 모션에서 팔꿈치는 두 타격 뒤에도 어깨보다 아래에서 몸의 같은 쪽에 머문다.

`draw_layer`는 북·북동·북서·서에서 `back`, 나머지 방향에서 `front`다. 저장소 루트에서 `python -m TestCode.checks_assets --require-complete`로 타격 이벤트, 칼끝·효과 기준점, 프레임 범위를 확인한다. `python -m SourceCode.main --smoke`는 SDL 입력으로 8방향 타격과 이동 공격의 레이어를 검사한다.

## Spine 편집과 내보내기

`spine/explorer-attack.spine.json`은 정지 공격을 위한 Spine 4.2.22 편집 원본이다. 본 11개, 슬롯 9개, `spine/images/`의 분리 PNG, 8방향 공격 애니메이션을 포함한다. 기본 셋업은 단검을 든 남서 방향이다. 각 방향의 애니메이션을 고르면 해당 방향의 파츠와 포즈가 로드된다. [Spine JSON 형식](https://en.esotericsoftware.com/spine-json-format)

Spine에서 **Import Data → New project**로 JSON을 열고, 이미지가 누락되면 **Images → Path**에 `./images/`를 지정한다. 가져온 프로젝트를 JSON 옆에 저장하면 이미지 상대 경로를 유지하기 쉽다. 제작 인계 당시 검증 범위는 게임용 PNG와 JSON이었다. Spine 편집기의 가져오기·네이티브 `.spine` 저장·편집기 내보내기 검증은 미실행 상태로 기록했다. [Spine 가져오기 안내](https://en.esotericsoftware.com/spine-import)

게임용 셀을 만들 때는 본 원점을 프레임의 (32,54)에 두고, 방향별로 위 13개 시점에서 64×64 투명 프레임을 샘플링한다. 공통 캔버스를 유지하고 `explorer.json`의 방향별 `rect`에 배치한다.
