## 1. N·NW 팔꿈치 수정

1. 보관한 N·NW 원본에서 0·16번 양발 착지, 8·24번 반대 발 통과, 31→0번 루프를 나란히 본다. 검 든 팔과 빈손 쪽 팔을 각각 따라가며 문제가 보이는 방향·팔·프레임을 먼저 표시한다. 수정 전 프레임과 제작 스크립트 사본 `work/rear-elbow-v2/`
2. `views.json`의 N·NW 어깨·팔꿈치·손 위치를 확인하고, `animate.py`의 `make_frame`에서 해당 방향의 팔 흔들림과 몸통 앞뒤로 가려지는 순서를 조정한다. 먼 팔이 가려지는 자세에서는 몸통 밖으로 억지로 꺼내지 않는다. 검과 손은 같은 움직임을 따르게 한다. 방향별 관절 좌표 `work/views.json` · 프레임 생성 코드 `tools/animate.py`
3. N·NW 각 32프레임을 다시 출력하고 NE는 수정된 NW의 같은 번호 셀을 반전한다. 기존 버전과 수정본을 정상속도와 0.25배속에서 각각 3회 이상 비교한다. 확대 화면에서는 팔꿈치가 반대로 꺾이거나 손목이 칼자루에서 어긋나는 순간을 찾고, 실제 표시 크기에서는 소매와 팔이 몸통에서 떨어져 보이는지 확인한다.
4. 양발의 궤적과 31→0 연결을 기존 프레임과 대조한다. 사용자에게 N·NW·NE 전후 비교 GIF를 보여 준 뒤 검수한 시트만 다음 에셋 커밋에 담는다.

## 2. 게임 속도에서 발 미끄러짐 조정

현재 게임의 걷기 속도는 약 89.44 논리 화면 px/s다. 기본 설정으로 0.8초에 약 71.55px를 이동한다. 아래 수치는 한 발이 체중을 받는 동안 제작 데이터의 접지점이 바닥 기준으로 밀리는 계산값이다.

| 방향 | 기본 설정에서 밀리는 거리 | 현재 속도에 그림의 보폭을 맞춘 주기 |
| --- | ---: | ---: |
| N·S | 약 25px | 0.23초 |
| NW·NE·SW·SE | 약 19px | 0.37초 |
| W·E | 약 15px | 0.47초 |

팔 수정 후에는 같은 이동 구간에서 기본값 `cycle_distance_px`와 그림의 보폭 `contact_cycle_distance_px`를 비교한다. 돌바닥 이음선 옆에 닿은 부츠가 얼마나 밀리는지, 특히 N·S에서 발걸음이 지나치게 빨라 보이는지 살핀다. 0.8초의 차분한 걸음을 살려야 한다면 먼저 보폭 수정을 시험하고 게임 속도를 바꾸는 결정은 별도로 다룬다. 미로에서 두 설정 비교 `review/game-sw-comparison.gif` · 방향별 측정값 `review/frame-qa.json`

## 3. 본편 연결과 배포

본편에 연결할 때는 `SourceCode/game_view.py`의 `View.locomotion_pose`와 `View.player_body`를 확인한다. 걷기 클립의 `image`, 현재 프레임의 `rect`, `flip_x`를 읽어 개별 시트의 셀을 그린다. `SourceCode/maze_model.py`의 `Game.animate_movement`에도 검수에서 선택한 보폭 값을 전달해 모델과 렌더러가 같은 보행 주기를 쓰도록 한다.

게임에서 Idle→Walk→Idle, 방향 전환, 달리기·공격 전환을 확인한다. 벽에 막혔을 때 실제 이동 거리에 맞춰 발이 멎는지, 횃불을 켰을 때 손과 불빛이 함께 움직이는지도 본다. 각 64×64 셀과 반전, 피벗, 루프를 다시 점검한 뒤 기능 브랜치에서 검수한 변경을 단계별로 커밋한다. 최종 검수 후 프로젝트 절차에 따라 `main` 통합을 진행한다.

GIF, 개별 프레임, 검수 기록과 제작 도구는 로컬에 보관한다. 다음 푸시 전에도 실제로 바뀐 시트와 실행 메타데이터의 경로를 하나씩 지정하고 커밋의 파일 목록을 확인한다.
